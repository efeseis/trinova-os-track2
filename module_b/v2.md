## 1. Overview

This module implements an independent computational pipeline for identifying and prioritizing drug candidates whose annotated biological mechanisms may be relevant to molecular vulnerabilities associated with a BUB1B molecular profile.

The workflow combines:

- An upstream BUB1B molecular profile.
- Functional variant consequence information.
- Mechanistic axis values.
- Drug and target annotations from the Broad Repurposing Hub.
- Development-context information.
- Rule-based mechanistic classification.
- Molecular relevance and development-context scoring.
- Mechanistic cluster diversification.

The pipeline produces a full candidate ranking, a repurposing shortlist, a discovery set, mechanistic cluster summaries, and complementary mechanistic-coverage hypotheses.

**The outputs are research hypotheses for further investigation. They are not evidence that a medication works, clinical recommendations, or treatment guidance.**

---

## 2. Scientific Rationale

The analysis uses BUB1B as its molecular reference.

BUB1B is associated with the mitotic spindle assembly checkpoint and the regulation of chromosome segregation. The upstream molecular profile provides information about functional variants, a declared loss-of-function hypothesis, and mechanistic axes.

The pipeline uses this information to explore whether compounds in the Broad Repurposing Hub have annotated targets or mechanisms associated with biological processes represented in the molecular profile.

The objective is to identify potentially relevant biological relationships, not to assume that inhibiting or modifying a related pathway will correct the underlying molecular alteration.

## 3. Input Data

The script requires two principal inputs.

### 3.1 BUB1B molecular profile

The pipeline searches for a compatible JSON profile in the configured Track 2 directory.

It checks the following preferred locations:

- `submission_track2_bub1b_consequence_profile.json`
- `repurposing_final_v3/submission_track2_bub1b_consequence_profile.json`
- `repurposing_final_v3/trinova_track2_v3_final_profile.json`

If none of these paths contains a compatible profile, the script searches recursively for JSON files under the Track 2 root directory.

The selected profile must contain:

- A `molecular_profile` object.
- A `functional_variants` list.
- A `mechanistic_axes` object.

The profile is checked for schema compatibility and, when a gene identifier is present, the expected gene is BUB1B.

The schema compatibility score is an input-selection heuristic. It does not validate the biological accuracy of the profile.

### 3.2 Broad Repurposing Hub

The second required input is:

`Repurposing_Hub_export.txt`

The file is read as a tab-separated dataset.

The script identifies and normalizes fields corresponding to:

- Drug or compound name.
- Molecular target.
- Mechanism of action.
- Development phase or status.

Records without a compound name are excluded. Duplicate records are removed using the normalized compound name, target, and mechanism-of-action fields.

The development status is inherited from the source dataset and is not independently verified by this script.

## 4. Molecular Profile Processing

The pipeline extracts the following information from the selected BUB1B profile:

- Declared loss-of-function hypothesis.
- Functional variant count.
- STOP_GAINED consequences.
- MISSENSE consequences.
- FRAMESHIFT consequences.
- SPLICE consequences.
- Mechanistic axis values.
- Variant phase status.
- Whether phase information is explicitly supported.

### 4.1 Molecular-support index

The script calculates a heuristic molecular-support index using the available profile information.

The contributions are:

| Profile feature | Contribution |
|---|---:|
| Declared LoF hypothesis | 1.00 |
| STOP_GAINED present | 1.00 |
| FRAMESHIFT present | 0.80 |
| SPLICE present | 0.80 |
| MISSENSE present | 0.25 |

The contributions are summed, divided by 2.0, and capped at 1.0.

This index is used as a prioritization modifier.

It is not a pathogenicity score, clinical causality estimate, or validated measure of disease severity.

### 4.2 Phase uncertainty

When phase is supported by the upstream profile, the phase uncertainty factor is 1.0.

When phase is not supported, the factor is 0.90.

The script does not infer compound heterozygosity in trans when adequate phase evidence is unavailable.

## 5. Mechanistic Classification

The pipeline defines seven mechanistic clusters.

| Cluster | Biological context | Molecular axis |
|---|---|---|
| `MPS1_TTK_SAC` | MPS1/TTK spindle assembly checkpoint | `MITOTIC_CHECKPOINT` |
| `AURORA_PLK_MITOSIS` | Aurora/PLK mitotic regulation | `MITOTIC_CHECKPOINT` |
| `CHROMOSOME_SEGREGATION` | Chromosome segregation and kinetochore | `CHROMOSOME_SEGREGATION` |
| `MICROTUBULE_MITOSIS` | Microtubule and mitotic spindle | `MICROTUBULE_MITOSIS` |
| `CELL_CYCLE` | Cell-cycle regulation | `CELL_CYCLE` |
| `APOPTOSIS` | Programmed cell death | `APOPTOSIS` |
| `DNA_REPLICATION_STRESS` | DNA replication and replication stress | `DNA_REPLICATION_STRESS` |

### 5.1 Classification method

The classification process searches the target and mechanism-of-action annotations for predefined terms.

Target matches are evaluated first.

If no target match is found, the script evaluates mechanism-of-action terms.

Each classification records:

- Assigned cluster.
- Cluster label.
- Associated molecular axis.
- Match source (`TARGET` or `MOA`).
- Rule-match confidence label.
- Matched term.

### 5.2 Match interpretation

The script uses two rule-match labels:

- `RULE_MATCH_HIGH`: a predefined target term was matched.
- `RULE_MATCH_MODERATE`: a predefined mechanism-of-action term was matched.

These labels describe the classification procedure. They do not represent experimentally validated biological confidence.

Compounds without a recognized match are assigned to `UNRESOLVED`.

The matching system is deterministic and rule-based. It may miss synonyms, incomplete annotations, or mechanisms not represented in its predefined vocabulary.

## 6. Molecular Relevance Scoring

Each resolved candidate receives a molecular relevance score.

The score combines:

1. The value of the corresponding molecular axis in the BUB1B profile.
2. A configurable weight assigned to that axis.
3. The source of the classification match.
4. The rule-match label.
5. The molecular-support index.
6. The phase uncertainty factor.

### 6.1 Mechanistic axis weights

| Molecular axis | Weight |
|---|---:|
| `MITOTIC_CHECKPOINT` | 1.00 |
| `CHROMOSOME_SEGREGATION` | 0.90 |
| `MICROTUBULE_MITOSIS` | 0.85 |
| `CELL_CYCLE` | 0.60 |
| `APOPTOSIS` | 0.20 |
| `DNA_REPLICATION_STRESS` | 0.10 |

These values are configurable heuristic parameters.

### 6.2 Match-source weights

| Classification source | Weight |
|---|---:|
| `TARGET` | 1.00 |
| `MOA` | 0.82 |
| `NONE` | 0.00 |

### 6.3 Rule-match weights

| Rule-match label | Weight |
|---|---:|
| `RULE_MATCH_HIGH` | 1.00 |
| `RULE_MATCH_MODERATE` | 0.85 |
| `UNRESOLVED` | 0.00 |

### 6.4 Consequence and phase modifiers

The consequence factor is:

```text
0.65 + (0.35 × molecular_support)
```

The phase uncertainty factor is:

```text
1.00  if phase is supported
0.90  if phase is not supported
```

The resulting molecular relevance score is therefore:

```text
molecular_relevance =
    axis_value
    × axis_weight
    × source_score
    × rule_score
    × consequence_factor
    × phase_uncertainty_factor
```

Candidates classified as `UNRESOLVED` receive a molecular relevance score of zero.

## 7. Development Context

The pipeline normalizes source-dataset phase and status labels into stable categories.

| Normalized context | Development score |
|---|---:|
| `APPROVAL_CONTEXT` | 1.00 |
| `LAUNCHED_DATASET` | 0.95 |
| `PHASE_4` | 0.90 |
| `PHASE_3` | 0.80 |
| `PHASE_2` | 0.65 |
| `PHASE_1` | 0.45 |
| `PRECLINICAL` | 0.20 |
| `DISCOVERY` | 0.10 |
| `UNRESOLVED` | 0.00 |

The development score represents source-dataset context, not a direct measure of clinical suitability.

**Regulatory-status limitation:** A Broad `Launched` label is not proof of current FDA approval or approval by another regulatory authority. The script does not independently verify approval, indication, market availability, or pediatric authorization.

## 8. Final Priority Score

Molecular relevance is normalized using min-max normalization across the loaded Broad catalogue.

The final priority score is:

```text
priority_score =
    (0.70 × molecular_relevance_norm)
    +
    (0.30 × development_score)
```

Candidates assigned to `UNRESOLVED` receive an additional reduction in their priority score.

### 8.1 Normalization limitation

Min-max normalization is relative to the composition of the loaded catalogue.

It is not an absolute biological or clinical evidence scale.

Adding or removing compounds, changing annotations, or changing the source dataset may alter normalized values and rankings.

If all molecular relevance values are identical, normalization returns zero for all candidates. The QC report records whether the resulting molecular relevance values are non-discriminating.

### 8.2 Priority classes

The script assigns descriptive priority classes:

- `HIGH_REPURPOSING_RELEVANCE`
- `HIGH_MECHANISTIC_RELEVANCE`
- `MODERATE_REPURPOSING_RELEVANCE`
- `MODERATE_MECHANISTIC_RELEVANCE`
- `LOWER_PRIORITY`
- `LOW_MECHANISTIC_SUPPORT`

These classes are derived from heuristic thresholds. They are not clinical evidence categories.

## 9. Mechanistic Cluster Summary

Resolved compounds are grouped by mechanistic cluster.

For each cluster, the pipeline calculates:

- Number of distinct compounds.
- Maximum molecular relevance.
- Mean molecular relevance.
- Maximum development score.
- Mean development score.
- Cluster score.
- Mechanistic rank.

The cluster score is:

```text
cluster_score =
    (0.70 × normalized maximum molecular relevance)
    +
    (0.30 × maximum development score)
```

Clusters are ranked by cluster score and maximum molecular relevance.

This summary provides a mechanism-level view of the catalogue and helps identify which biological areas receive the strongest computational support under the configured model.

## 10. Candidate Selection

The pipeline produces two separate candidate collections.

### 10.1 Repurposing shortlist

The repurposing shortlist includes resolved candidates with one of the following development contexts:

- `APPROVAL_CONTEXT`
- `LAUNCHED_DATASET`
- `PHASE_4`

Candidates must also meet a minimum normalized molecular relevance threshold of 0.15.

Selection is ordered by:

1. Priority score.
2. Normalized molecular relevance.
3. Development score.

Diversification limits:

- Maximum of twelve candidates.
- Maximum of three candidates per mechanistic cluster.

This shortlist is a research-prioritization output. Inclusion does not establish that a compound is currently approved or suitable for a particular patient.

### 10.2 Discovery set

The discovery set includes resolved candidates with the following development contexts:

- `PRECLINICAL`
- `DISCOVERY`
- `PHASE_1`
- `PHASE_2`
- `PHASE_3`

Candidates must meet a minimum normalized molecular relevance threshold of 0.20.

Selection is ordered by:

1. Normalized molecular relevance.
2. Priority score.

Diversification limits:

- Maximum of twenty candidates.
- Maximum of four candidates per mechanistic cluster.

The discovery set preserves candidates with potentially relevant mechanisms that are at earlier development stages.

It is not a list of approved or clinically available medications.

---

## 11. Complementary Mechanistic-Coverage Hypotheses

The pipeline generates exploratory hypotheses based on pairs of distinct mechanistic clusters.

For each pair, it evaluates the corresponding molecular axes and their configured weights.

The coverage score is:

```text
mechanistic_coverage =
    (axis_value_a × axis_weight_a)
    +
    (axis_value_b × axis_weight_b)
```

Pairs associated with the same molecular axis are excluded.

The highest-scoring twenty pairs are retained.

These outputs describe potential complementary coverage of molecular axes. They do not identify validated drug pairs.

**No drug synergy, efficacy, safety, pharmacological compatibility, or clinical suitability is established.**

The combination hypotheses are not drug-pair recommendations.

## 13. Configuration and Execution

The script is designed for Python 3.13 and uses:

- Python standard library.
- `pandas`.

Install the required external dependency:

```bash
pip install pandas
```

### 13.1 Environment configuration

The script supports three environment variables:

| Variable | Purpose |
|---|---|
| `TRINOVA_BASE` | Base directory for the local project |
| `TRINOVA_TRACK2_ROOT` | Directory containing upstream Track 2 profile JSON files |
| `TRINOVA_BROAD_HUB` | Full path to the Broad Repurposing Hub export |

If these variables are not configured, the script uses its default Windows paths.

### 13.2 Windows CMD example

Configure the paths in Windows Command Prompt:

```cmd
set TRINOVA_BASE=C:\path\to\project
set TRINOVA_TRACK2_ROOT=C:\path\to\project\track2_outputs
set TRINOVA_BROAD_HUB=C:\path\to\Repurposing_Hub_export.txt
```

Then execute:

```cmd
python trinova_track2_final.py
```

Replace the example paths and Python filename with the actual local locations.

The script automatically creates the `output` directory next to the Python file if it does not already exist.

## 15. Limitations

### Molecular evidence

- A STOP_GAINED annotation alone does not establish clinical causality.
- A missense annotation is not automatically pathogenic.
- The molecular-support index is a heuristic prioritization modifier, not a pathogenicity score.
- The script does not independently validate upstream variant annotations.
- Compound heterozygosity in trans is not inferred without adequate phase evidence.

### Mechanistic classification

- Classification is based on predefined text matching.
- Synonyms and incomplete annotations may result in missed matches.
- A matched target or mechanism does not prove a functional relationship with the molecular alteration.
- Rule-match confidence is not experimental evidence.

### Scoring

- Axis weights and development scores are heuristic parameters.
- Thresholds are not empirically calibrated estimates of treatment response.
- Min-max normalization depends on the composition of the loaded catalogue.
- Rankings may change when the input dataset or annotations change.

### Drug development and regulatory status

- Development context is inherited from the source catalogue.
- The script does not independently verify regulatory approval.
- A Broad `Launched` label must not be treated as proof of current approval.
- Approval for a specific indication, market availability, and pediatric authorization require independent verification.

### Clinical and pharmacological interpretation

- The pipeline does not establish efficacy or safety.
- It does not evaluate dose, pharmacokinetics, pharmacodynamics, or drug interactions.
- It does not establish patient suitability.
- Potential inhibition of mitotic pathways could be ineffective or harmful and requires independent experimental assessment.

### Combination hypotheses

- Complementary axis coverage is not evidence of drug synergy.
- The script does not evaluate combination toxicity or clinical feasibility.
- Experimental validation is required before any pharmacological interpretation.

This module is designed to support hypothesis generation for drug repurposing research.

**Mechanistic relevance is a basis for further investigation, not proof of clinical efficacy.**
